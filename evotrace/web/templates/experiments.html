Interpretation, Methodology & Limitations

1. Ground Truth & Metrics Formulation

The synthetic benchmark generator produces controlled collections with known field distributions. Document Impact Detection compares the documents actually mutated against the synthetic ground truth count, computing true positives (TP), false positives (FP), and false negatives (FN). Query Impact Classification evaluates whether the static intersection rules correctly identify affected versus disjoint queries compared against labeled query dependencies. Recovery Correctness is measured by directly comparing post-recovery documents against bit-level pre-operation ground truth captured prior to transformation.

2. Scope and Empirical Boundaries

Synthetic Data vs. Real Workloads: Experiments utilize synthetic data with controlled variance. Real-world document schemas often feature deeper nesting, polymorphic arrays, and unstructured free-text fields.

Query Registration Boundary: Impact analysis is evaluated against registered declarative queries. EvoTrace does not claim arbitrary static source code AST analysis of external Python, Java, or Node.js application codebases.

Hardware & Engine Latency: Timing metrics reflect local CPU and I/O performance. When operating against local mongomock, networking roundtrips are negligible compared to networked MongoDB deployments.
